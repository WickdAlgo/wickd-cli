### 2026-08-28 — canonical thin client and package/runtime proof

All shipped clients now deserialize the API's named envelopes, validate their
schema version and contract identity, and preserve decimal strings. Fetch
resolves the API-published exchange symbol and saves aliases separately;
analyze and backtest send only a host-side alias or complete cached identity.
VWAP period/level-period overrides and configured engine settings cross the
wire, as does the configured structure pivot. The vendored schema/sample set
is pinned to the accepted `wickd-api` review head `f7f9268` and covered by
contract tests.

Release build is warning-free and the final suite passes **27/27**. A fresh
`wickd-cli.0.1.0.nupkg` installed into an empty tool directory; `wickd --help`,
`analyze vwap --help`, `backtest --help`, and selector-validation exit-code-two
paths ran from that installation. The package contains no Core, Inspection,
adapter, or CCXT assembly. Injecting `Wickd.Core.dll` into a copy made
`scripts/verify-package.sh` fail as required, while the untouched package
passed. A separate post-commit code pass ran **3 perturbations, 0 stayed green,
0 did not compile, 0 skipped**: dataset plus market reaching backtest, a future
contract version being accepted, and a canonical decimal string mapping to the
wrong value all failed their named tests as required.

For runtime proof, that final packed tool called an actual Release API process
over HTTP against its host-side alias/cache. VWAP reported 5 candles, the exact
00:00–00:25 UTC range, 0 gaps, one daily series, and no previous-close levels;
backtest created `runtime-final-package` with 5 candles, 2 structure events,
and 0 gaps. The API's deterministic fake-exchange endpoint separately drives
fetch, alias save, alias/identity analyze, and alias backtest without an
external market call.
