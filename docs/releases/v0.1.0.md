# v0.1.0 candidate contract

The package version remains 0.1.0. This candidate adds authenticated catalog,
wallet, server risk-preview, setup lifecycle and note revision commands on top of the workspace
client candidate. See [the command reference](../wallet-setups.md) for complete
request files, retry semantics, ETags, cursor handling and current server limits.

The client vendors the generated API v2 JSON schemas and synthetic samples from
the wallet/setup API candidate and lifecycle checkpoint `3b9fa78`. Setup lists
require `snapshotCursor`; detail supports the same frozen cursor; response note
`supersedesId` remains optional for earlier v2 payloads. Schema validation runs
locally using JsonSchema.Net; financial JSON remains exact strings. There is no
project/package reference to API, Core, inspection or exchange assemblies.

Required candidate verification:

```sh
dotnet test Wickd.Cli.slnx
dotnet pack src/Wickd.Cli/Wickd.Cli.csproj -c Release -o artifacts
scripts/verify-package.sh artifacts/wickd-cli.0.1.0.nupkg
```

Tests exercise generated request/response samples, command dispatch, identity and
cursor encoding, session/workspace requirements, explicit idempotency keys,
strong ETags, exact request-byte retries, schema refusal and remote error status
preservation. Lifecycle tests cover command/body intent, unchanged request bytes,
required write ETags, optional legacy note fields, required list snapshot metadata
and frozen-detail cursor forwarding. A clean package boundary proves packaging isolation only. Local
synthetic checks do not establish a deployed authenticated API or qualify live
wallets, FX, provider imports, fills, accounting or performance. Those remain
producer/overall-goal scope. Publication, merge and deployment retain their
separate authority gates.

## Native paper wallet fills (CLI #23)

The client vendors the canonical paper fill schemas and synthetic samples from
API checkpoint `08d8f8164635635e0cced48ea3b2d208aa586300`. `wallet fills
create/list/get/correct` forward immutable paper evidence, exact request bytes,
explicit idempotency keys and the correction ETag. Frozen reads retain API
cursors. The records remain unassigned with `unprojectedIncomplete` accounting
status; the client has no allocation, valuation, execution, or order behavior.
See [wallet and setup commands](../wallet-setups.md).
